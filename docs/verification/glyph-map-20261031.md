# Rejected glyph lookup experiment — 2026-10-31

Replacing the glyph atlas's ordered map with a hash table did not establish a
reliable complete-workload gain. The candidate lost four of six alternating
pairs and was reverted before changing either host binary.

The candidate preserved the exact face/glyph/quantized-size key, used integer
hash combination, and relied on unordered-map reference stability across
rehashes. Only the private atlas container and key comparison changed. This
was not an ABI, font rasterization or pixel-format change.

## Measurement

The [selection profiler](core-selection-profile-20261031.md) provided separate
baseline and candidate executables linked to their respective GCC Release
libraries. Sampling and allocation profiling were **off** for these runs.
Each process performed 120 warmups followed by 20,000 full selection updates.
Six alternating pairs total **240,000 measured updates**. Every setter returned
success; all twenty final targets and asset availability were checked per run.
The diagnostic uses fixed fonts and direct C ABI setters, so these are core
update measurements, not real-font host frame times. Setter cost is outside
the reported update interval.

| Pair | Baseline mean update (ms) | Candidate mean update (ms) | Candidate change |
|---|---:|---:|---:|
| 1 | 0.369732 | 0.348671 | -5.70% |
| 2 | 0.375010 | 0.379394 | +1.17% |
| 3 | 0.348253 | 0.349518 | +0.36% |
| 4 | 0.356559 | 0.347580 | -2.52% |
| 5 | 0.353213 | 0.362267 | +2.56% |
| 6 | 0.388537 | 0.400481 | +3.07% |

Median paired change is **0.77% slower**. Comparing the unpaired medians of run
means would suggest about a 2% improvement, but that obscures the four losing
pairs. There is insufficient evidence to accept the change. This does not
prove hash tables are universally slower; it rejects this implementation for
the measured complete selection workload.

## Restoration and evidence

The atlas header was restored byte-for-byte. The first restoration build did
no work because copying the older file preserved its timestamp; that log is
retained. After refreshing the source timestamp and rebuilding, the core
archive SHA-256 exactly matched the pre-experiment library:

`9ee47cba558a6e81486d1a4b38ddae0d9709116f64b8ca32a73bc8570f72903a`.

Evidence is under `.utmp/render-audit-20261030/`: baseline/candidate atlas
headers, build/restoration logs, and `core-selection-profile/glyph-map-pairs/`.
`compare_glyph_map.py` and both standalone executables remain available.
The adjacent receipt hashes the evidence and records the decision. No host
rebuild or host performance claim is made, and no production tests are claimed
for the rejected candidate. Production source and the active GCC diagnostic
library are back to their verified pre-experiment state.

Next shared-core investigation: repeated style/font resolution during paint
preparation, especially work performed before discovering that a box has no
transform. Measure complete-workload effects before committing a cache or
changing invalidation behavior.
