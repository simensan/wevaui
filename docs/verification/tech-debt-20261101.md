## Remaining debt, in priority order

1. **P1 — Attribute host-engine memory growth and qualify its adopted SDK.** The
   [host memory audit](host-memory-20261101.md) reproduces +78.20 MiB private
   memory over five minutes of reloads at 60 updates/s in a preserved historical
   SDK. That SDK predates current main; these counters prove neither current-core
   ownership nor a fix. Next: instrument allocations across the bridge, core,
   renderer and retained runtime resources, then repeat matched idle/reload
   controls using an explicitly identified current SDK. Do not label it closed
   from Unity/Godot results.
2. **P2 — Bound image URL churn in long-lived documents.**
   `libweva/include/weva/image_store.h` intentionally retains decoded images and
   failed URL entries until reset. Fixed-content reuse benefits from that cache,
   but a long-lived document visiting continually new URLs has no byte budget.
   This is a design limit, not a newly demonstrated unreachable-memory leak.
   Returning borrowed decoded-image pointers and retaining filtered paint data
   makes arbitrary eviction unsafe. Implement trimming at an owned publication/
   layout/paint boundary with resource-generation and source-swap regressions;
   do not bolt on a host-specific LRU.
3. **P2 — Reduce lifecycle coupling when changing the owning subsystem.** The
   ABI implementation is 9,696 lines, Godot's document node 3,915, paint 4,896,
   and block layout 2,237. Size alone is not a defect, but it makes callback,
   reload and resource ownership harder to review. Extract coherent ownership
   domains alongside the next substantive change, retaining the existing C ABI
   and both-host regressions. A wholesale cosmetic file split is not the next
   priority.
4. **P2 — Complete consumer acceptance and platform qualification.** Physical
   IME/gamepad/touch and accessibility, consumer-specific IL2CPP stripping and
   asset loading, unverified host platforms and long hardware-rendered soaks
   remain adoption work. See [readiness](../PRODUCT_READINESS.md); historical
   scoped results must not become universal support claims.

No new runtime leak was confirmed by this source/tooling audit. The next runtime
investigation should start with host-engine allocation ownership; the next reusable
memory feature should be a safe image-cache budget. Both have more user value
than further rearranging the large source files.
